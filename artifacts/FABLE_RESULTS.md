All three runs prune the same seed-0 dense baseline network ([196,10,10,10],

| selector | run | last sparsity % with acc >= 0.85 | last sparsity % with acc >= 0.50 | first step acc < 0.50 (sustained) | sparsity % at collapse |
|---|---|---|---|---|---|
| Manifold d_W search | `artifacts/e05_stupidity_point/sparsified/sparsification_log.csv` (2160 rows) | 78.29 | 90.51 | 1956 | 90.56 |
| Magnitude argmin abs(w) | `artifacts/e15_magnitude_full/magnitude_sparsified/magnitude_sparsification_log.csv` (2160 rows) | 74.26 | 88.89 | 1921 | 88.94 |
| Kwon (first-order Taylor of d_W) | `artifacts/e16_kwon_full/kwon_sparsified/kwon_sparsification_log.csv` (2160 rows) | 58.43 | 77.59 | 1677 | 77.64 |

Note on the Kwon selector: its score (dd_W/dw_ij)^2 * w_ij^2 is exactly the
squared *first-order Taylor estimate* of the change in d_W when w_ij -> 0,
obtained from a single gradient call on the same data-free manifold
objective d_W (uniform-noise Omega). It is therefore a data-free, O(B·C)-cost
approximation of the manifold search itself — the relevant framing for the
thesis: the exhaustive O(N·B·C) search and the single-gradient Taylor proxy
optimise the same functional.

## (d) Corrected E3b (e03_width_200) numbers — Task 3 verification

**Finding: the flagged "denominator bug" understates the problem. The
archived e03/e04 architecture runs never used their configured topologies.**

Evidence (all reproducible from the artifacts):

1. `experiments/e03_width_200.json` specifies topology [196,200,200,10]
   (81,200 prunable weights), but `artifacts/e03_width_200/W_*.npy` have
   shapes (10,196), (10,10), (10,10) — the baseline [196,10,10,10] topology.
2. MD5 of `artifacts/e03_width_200/W_*.npy` is byte-identical to
   `artifacts/baseline/W_*.npy` (9194e70e/ec137b93/837cabfb). The same holds
   for e03_width_50, e04_depth_2layer and e04_depth_4layer.
3. No `training_log.csv` exists in any of those four artifact folders — the
   configured networks were never trained; the baseline dense net was copied
   in, which made `run_experiments.sh` skip the training step (it only checks
   that `W_0.npy` exists).

Corrected numbers for the run actually performed (a re-run of the baseline
network under a fresh Omega sample):

- TRUE total prunable weights of the network that was pruned: **2160** (not 81,200).
- Final NZ at step 499: **1661**.
- Correct sparsity: 1 - 1661/2160 = **23.10%** (the logged `sparsity` column, 23.10%, is arithmetically correct *for the baseline net*).
- Final val_acc: **0.662** (dense 0.916).
- If the logged NZ were (incorrectly) interpreted against the intended width-200
  denominator: (81200-80701)/81200 = 0.61% — neither number describes a width-200 experiment.

**Consequence:** the "width-200 anomaly" discussed in the thesis (accuracy
collapse 0.916 -> 0.662 at 23.1% sparsity) is NOT an architecture effect. It
is a re-run of the baseline network whose trajectory differs only through the
resampled Monte-Carlo Omega; cross-run final accuracy under identical configs
spans 0.780-0.912 (e10 seeds), and the e03/e04 spread is the same
phenomenon. Table 7.5 and section 7.3 of the thesis draft should be rewritten:
there are currently NO valid width/depth scaling results.
